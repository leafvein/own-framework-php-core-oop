## Response-based Rendering
Currently, our application is echoing output directly from the controller, making the controller responsible for business logic, presentation, HTTP output. 
To reduce controller's responsibilities and implement SoC(Separation of Concern), we will use a Response-based rendering.

## Create Response Class
Create the Response class in the `app/Core/Response.php` file as like below:

```php
<?php
declare(strict_types = 1);

namespace App\Core;

class Response
{
    public static function view(string $view, array $data = [])
    {
        extract($data);
        $content = self::render($view, $data);
        include __DIR__ . '/../../views/layout.php';
        exit;
    }

    protected static function render(string $view, array $data = [])
    {
        ob_start();
        extract($data);
        include __DIR__ . '/../../views/' . $view . '.php';
        return ob_get_clean();
    }
}

```
**Code Explain**
> ```php
> public static function view(string $view, array $data = [])
> {
>      extract($data);
>      $content = self::render($view, $data);
>      include __DIR__ . '/../../views/layout.php';
>      exit;
> }
> ```
> The `view` function will receive a view file and dynamic data for the view (html template) file,    
> Convert each array element of the `$data` into variable.
> Render the view file and store output in `$content`. 
> Then load the layout file to display the page using `$content`. 
> After sending the response, `exit` will confirm that the request has been completed.
>
> ```php
> protected static function render(string $view, array $data = [])
> {
>     ob_start();
>     extract($data);
>     include __DIR__ . '/../../views/' . $view . '.php';
>     return ob_get_clean();
> }
> ```
> `ob_start()` starts output buffering to capture the output generated by the view file.
> Convert each array element of the `$data` into variable.  
> Included the specified view file to generate output and store in the output buffer instead of sent directly to the browser.  
> `ob_get_clean()` returns the captured output as a string and clears the output buffer.

## Create Template and View File
Create layout file `views/layout.php` :
```php
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <title><?= $title ?? 'My OOP App' ?></title>
</head>
<body>
<header><h1>My OOP App</h1></header>
<main>
<?= $content ?>
</main>
<footer>Copyright &copy; <?= date('Y') ?></footer>
</body>
</html>

```
**Code Explain**
> This is a PHP layout (template) file. It is defining the common HTML structure of a web page and displaying dynamic content passed from the application controller.
>
> ```php
> <title><?= $title ?? 'My OOP App' ?></title>
> ```
> Display page title using `$title` variable if available otherwise display default value.
>
> ```php
> <?= $content ?>
> ```
> Display main page content using `$content` variable that will contain the rendered output (using Output Buffer) of the view file.
> 
> ```php
> <footer>Copyright &copy; <?= date('Y') ?></footer>
> ```
> Footer will display current year.

Create the `views/home.php` file:

```php
<p><?= htmlspecialchars($message) ?></p>
```

**Code Explain**
> Display dynamic message safely using `htmlspecialchars()` function. 
> We used PHP short echo tag `<?= ... ?>` to display the message on the page.

## Use View Response

Our `view` Response is configured, we will use it in the Controller. Open the `app/Controllers/HomeController.php` file and edit as shown below:
```php
use App\Core\Response;

return Response::view('home', ['message' => 'Welcome to My OOP App']);

```

**Code Explain**
> Imported response class to use in the Controller.
> Display content of the specified view file `home.php` and use array to generate dynamic content of the page.
